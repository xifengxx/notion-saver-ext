# 图片上传性能优化 — 竞品调研

> 日期：2026-05-25 | 版本：v0.7.0 预研

## 各工具图片处理方式

| 工具 | 策略 | 细节 |
|------|------|------|
| 官方 Web Clipper | 全量上传 | 下载后上传 Notion S3/CloudFront，不保留外部 URL |
| Save to Notion 扩展 | 全量上传 | 生成 `file` 类型图片块，URL 1小时后过期 |
| Evernote Web Clipper | 全量上传 | 下载存储为笔记内资源，计入月度上传配额 |
| Joplin Web Clipper | 下载为本地资源 | `:/resource-id` 引用，WordPress 超链接图片偶有例外 |
| Wallabag | 可配置开关 | `Download images locally` 开关，最接近混合方案 |

## 行业共识：全量上传是主流，没有混合方案

没有已知扩展提供「外部 URL 优先 + 失败时 fallback 上传」的混合方案。

## 外部 URL 引用图片的三个致命问题

1. **Referrer 检查**：部分 CDN 校验 `Referer` 头，Notion 发出的请求不带原站 referrer，被拒绝
2. **签名过期**：类似 S3 签名 URL 的临时链接会过期
3. **源站删除**：图片被删除或路径变更后直接挂掉

技术缓解手段（`referrerpolicy="no-referrer"`、`onerror` 回退、代理下载）没有银弹。

## 性能对比

| 维度 | 外部 URL | 上传重托管 |
|------|----------|-----------|
| 保存速度 | 快（无上传） | 慢（逐个下载+上传） |
| 渲染速度 | 慢（多外部请求） | 快（Notion CDN 单源） |
| 存储成本 | 无 | 计入工作区配额 |
| 可靠性 | 依赖源站 | 高 |

## Notion API 图片块类型

- `external`：引用外部 HTTPS URL，永久有效
- `file`：上传到 Notion S3，临时签名 URL，1小时过期

## NotionSnap 当前实现

并行下载 + 排队上传，已与竞品对齐。

## 可改进方向

- 小图片（<100KB）尝试同时用外部 URL 作为瞬时展示占位符——但依赖 Notion 行为，不可控
- 真正有效的优化在传输层：预连接、HTTP/2 多路复用
- 可以考虑给用户选择：速度优先（外部 URL）vs 可靠性优先（上传）

## 结论

当前方案是正确路径，架构不需要大改。性能优化空间在上传队列和网络层面。
